## Задание 1. Один файл — две среды выполнения

Файл `js/hello.js` запущен одним и тем же кодом в двух средах.

Фактический вывод в Node.js (терминал):

```text
Студент: Alexey Panov
Группа: EFBO-13-25
Практическая работа: 1
JavaScript успешно запущен
Тип document: undefined
```

Фактический вывод в браузере (Chrome, вкладка Console): те же четыре строки, но последняя — `Тип document: object`.

**Различие:** `document` — объект браузерной среды, он предоставляет доступ к HTML-странице (DOM). Обычный запуск файла через Node.js не создаёт страницу, поэтому `document` там не определён и `typeof document` даёт `undefined`. В браузерной вкладке объект существует, поэтому `typeof document` даёт `"object"`. Весь вывод в обоих случаях оказался в консоли (терминал / Console), а не на HTML-странице.

## Задание 2. Исследование типов и преобразований

Файл `js/types.js`. Перед запуском записано предсказание, затем результат проверен фактически.

| Выражение | Ожидание до запуска | Фактическое значение | Тип результата | Объяснение |
|---|---|---|---|---|
| `"8" + 2` | `"82"`, string | `82` | string | Если хотя бы один операнд `+` — строка, оператор выполняет конкатенацию: число `2` приводится к `"2"` и приклеивается. |
| `"8" - 2` | `6`, number | `6` | number | У вычитания нет «строкового» режима: операнды всегда приводятся к числам, `"8"` → `8`. |
| `Number("8") + 2` | `10`, number | `10` | number | Явное преобразование строки в число, затем обычное числовое сложение. |
| `"12" > "3"` | `false`, boolean | `false` | boolean | Две строки сравниваются как строки, посимвольно: `"1"` меньше `"3"`, поэтому `"12" < "3"` независимо от числовых значений. |
| `12 === "12"` | `false`, boolean | `false` | boolean | Строгое равенство не приводит типы: number и string разных типов, сравнение сразу ложно. |
| `Number("")` | `0`, number | `0` | number | Пустая строка — специальный случай: преобразуется в ноль, а не в `NaN`. |
| `Number("text")` | `NaN`, number | `NaN` | number | Непреобразуемая строка даёт `NaN`; при этом тип `NaN` — `number`, поэтому проверка на `NaN` нужна отдельно (`Number.isNaN`, `Number.isFinite`). |
| `Boolean("false")` | `true`, boolean | `true` | boolean | Логическое преобразование не читает текст: любая непустая строка истинна, даже если это слово «false». |
| `typeof null` | `"object"`, string | `object` | string | Историческая особенность языка: `typeof` возвращает `"object"`, хотя `null` — отдельное примитивное значение. Значение выражения — строка `"object"`, и тип этой строки — `string`. |
| `typeof NaN` | `"number"`, string | `number` | string | `NaN` принадлежит числовому типу («не-число» как результат числовой операции). Значение выражения — строка `"number"` типа `string`. |

**Вывод по заданию:** одного `typeof` недостаточно для проверки числовых данных (`typeof null === "object"`, `typeof NaN === "number"`, `Number("") === 0`), для допустимости значений нужны `Number.isInteger()`, `Number.isFinite()` и проверки диапазона.

## Задание 5. Поиск логических ошибок через DevTools

**Исходный (ошибочный) вывод программы** — зафиксирован запуском до исправления:

```text
Выполнено: 32
Осталось: -24
Контрольная сумма: 6
```

Исключения не возникло, но результат неверный: `32` вместо `5`, `-24` вместо `3`, `6` вместо `10`.

**Ход отладки:** в DevTools (вкладка Sources) поставлена точка останова на строке вычисления `completedTotal`; после перезагрузки страницы в области Scope видно, что `completedText` и `additionalText` — строки `"3"` и `"2"`, а не числа. Шаг Step over показал, что `completedTotal` получил значение строки `"32"`. Вторая точка останова внутри цикла показала: `taskNumber` принимает значения 1, 2, 3, и на `taskNumber = 3` после увеличения на 1 (`4 < 4`) цикл завершается, задача № 4 в сумму не входит.

| Ошибка | Что наблюдалось | Причина | Исправление | Результат после исправления |
|---|---|---|---|---|
| Обработка количества задач | `Выполнено: 32`, `Осталось: -24` | Операнды — строки, `+` выполнил конкатенацию: `"3" + "2"` → `"32"`; вычитание затем привело `"8" - "32"` к `-24` | Явное преобразование: `Number(completedText) + Number(additionalText)` | `Выполнено: 5`, `Осталось: 3` |
| Граница цикла | `Контрольная сумма: 6` (1+2+3) | Условие `taskNumber < 4` останавливает цикл на 3, номер 4 не включён | Условие изменено на `taskNumber <= 4` | `Контрольная сумма: 10` |

## Дополнительное задание. Вариант А — данные поступают строками

Файл `js/progress-input.js`: входные значения — строки (`"7"`, `" 2 "`). Порядок обработки: проверка `typeof` (переданы именно строки, `null` и `undefined` отклоняются) → `trim()` → отклонение пустой строки → `Number()` → `Number.isNaN` → `Number.isFinite` → целочисленность → диапазон → обычный расчёт как в задании 3.

Собственные проверки (помимо контрольной):

| Входные данные | Ожидание | Фактический результат | Итог |
|---|---|---|---|
| `"7"`, `" 2 "` (контрольная) | Сводка как в задании 3 | `Прогресс: 28.6%`, `Статус: В работе` | Пройдено |
| `"12"`, `"5"` | 41.7%, «В работе» | Совпадает | Пройдено |
| `"abc"`, `"2"` | Ошибка без исключения | `Ошибка: строку не удалось преобразовать в число` | Пройдено |
| `""`, `"5"` | Ошибка | `Ошибка: получена пустая строка` | Пройдено |
| `"2.5"`, `"1"` | Ошибка | `Ошибка: значения должны быть целыми числами` | Пройдено |
| `"Infinity"`, `"0"` | Ошибка | `Ошибка: число должно быть конечным` | Пройдено |
| `null`, `"2"` | Ошибка | `Ошибка: входные данные должны быть строками` | Пройдено |
| `undefined`, `"1"` | Ошибка | `Ошибка: входные данные должны быть строками` | Пройдено |
| `"8"`, `"9"` | Ошибка | `Ошибка: значения вне допустимого диапазона` | Пройдено |

**Почему недостаточно вызвать `Number()` и проверить, что результат не отрицателен:** `Number("")` и `Number(" ")` дают `0`, и такой ввод прошёл бы проверку как «ноль задач»; `Number("2.5")` даёт дробь, формально неотрицательную; `Number("Infinity")` даёт `Infinity` — она больше нуля; `Number("abc")` даёт `NaN`, а сравнение `NaN < 0` ложно, то есть `NaN` прошёл бы проверку «не отрицателен». Кроме того, `null` и `undefined` не являются строками и должны быть отклонены до преобразования. Поэтому нужны `trim()`, проверка на пустую строку, `Number.isNaN()`, `Number.isFinite()`, `Number.isInteger()` и диапазон.
